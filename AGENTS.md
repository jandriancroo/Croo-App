
- Subdirectories have their own AGENTS.md (supabase/functions/AGENTS.md holds Theo/Quick Nudge rules); read before changes.
- Role settings (role_permissions, role_notification_settings) are per organization; new orgs are seeded from *_template tables by trigger. Why: one org admin must not change every org.
- Labor shift pairing lives only in _labor_pair_shifts; labor_day_user_totals, labor_shifts and pay-period close guard all read it. Why: one source of truth.
- Auto clock-out is decided only by public.run_auto_clock_out() (pg_cron, SQL, no HTTP) and the auto_clock_out_settings.mode switch, changed by migration only. Why: one writer, no request-supplied stores or dates.
- Toast sales arrive only through toast-sync day payloads (export > live; api = export rank); fetchers are swappable, never write sales_cache directly. Why: homemade today, official API later without touching readers.
- Toast employee mappings immediately sync matching toast_shifts rows by location + Toast user ID. Why: badges and schedule pairing update without waiting for the robot.
- Interview calendar files expose only signed CrooHQ join URLs; the raw video-call URL stays server-side. Why: Google Calendar rewrites raw Meet links during import.
- Store counting pack comes only from get_store_pack_lens / v_store_pack_lens; inventory_items.pack_quantity_override is retired, never read. Why: per-store pack matches what the store buys.
- Shift-swap phone alerts (offered / claim / approved) are queued only by the shift_offers + shift_offer_claims triggers into alert_queue; clients never send them. Why: alerts fire no matter which screen made the change.
- Marketplace Assign/Approve/Undo refresh only the selected shift's published snapshot in the same RPC transaction; unpublished weeks are rejected, and the schedule lifecycle marks only that shift's history sent. Why: confirmations cannot leave draft assignments or publish unrelated edits.

- POS list: server only _shared/posSources.ts, client only src/lib/pos/liveSales.ts; never a hard-coded fallback POS (unknown = null). Why: missing lists mislabeled Hayward.
- New data/POS source: update data_point_registry in the same migration. Why: one writer map.

- SpookifiedEffects is theme/Dashboard-scoped; lightning stays in TheoVoiceOrb. Why: isolate decorations from data and other themes.
- Lovable never edits watch/, ios/ or widgets/ (Mac Studio Xcode only); watch/widget data rules live in supabase/functions/watch-device-service/AGENTS.md. Why: no merge clashes.
- TestFlight "What to Test" notes come only from ios/TESTFLIGHT_NOTES.md ("## Next build", plain English, one line per native change); Croo Builder Ship posts them and files them under the build. Why: testers always see what changed.
- Single-choice view switches use ui/segmented-control.tsx and weekday multi-pickers use ui/day-toggle-row.tsx (callers keep their own toggle function). Why: one shape app-wide without touching saved values.
- Labor pace comes only from get_labor_pace (required unpaid breaks sized like the schedule meal rule; on-track band = _labor_pace_on_track_band(); worked = the same labor_day_totals / labor_cache row get_store_labor reads; today's sales pace = sales_pace_today, kept equal to cubeMetrics.computePace by scripts/check-labor-pace-sql.ts). Why: labor pace, Dash and labor totals never disagree.
- Smart Close only changes closers' remaining time in get_labor_pace, from labor_close_habits (nightly refresh_labor_close_habits), only where labor_smart_close_settings.enabled; accuracy lives only in labor_pace_scorecard (11/2/5/7/9 store-time snapshots, 3 AM fill; read via get_labor_pace_report). Theo cut history only via get_cut_history. Position layer (use_position flag) is OFF everywhere — Oct 2026 back-test lost to 3-layer. Why: one learning path; off stores get plain pace.
- Page titles use components/PageTitle.tsx; the status line above the title comes only from its status prop (omitted = today's store date, null = none), and counts must reuse page data or one head-count under the user's own session (hooks/usePageStatus.ts). Why: same title height everywhere and no permission leaks.
- Promo trackers live only in promo_trackers (one record per promo; brand promo beats org contest; one per owner at a time) and are read/written only via get_active_promo_tracker / list_promo_trackers / save_promo_tracker / end_promo_tracker; never as dashboard_widgets rows, and they can't be hidden. Why: per-store copies left duplicate and leftover trackers.
- Standard checklist schedule (which day a list shows, day vs week/month/quarter scoring) is decided only by lib/taskHistory/schedule.ts (byte-identical _shared copy) and its SQL twins checklist_shows_on / checklist_period_kind / _start / _end; `frequency` is a derived legacy value kept filled by trigger. Why: every screen, alert and email shows the same lists on the same days.
- System announcements use system_alerts and system_alert_receipts, delivered through get_next_system_alert and the existing startup sequencing; only super admins manage them. Why: reusable once-per-user delivery without stacking popups or changing operational alerts.
- Dash quick tasks (PIN, I-9, Read & Sign, temp tasks, events, catering, cash counts, spot check) render only as rows inside the AssignedTemporaryTasks Quick Tasks card via QuickTasksSection extraRows; window rules live in lib/quickTasks/extraRows.ts. Why: one home, nothing hidden on quiet days.
- Toast Status is a native-only, token-scoped standalone service; only its service-role restart RPC writes restart requests, with a per-location transaction lock. Why: no existing Toast/punch changes, no client location overrides, and no duplicate concurrent restarts.
- iPhone Duo: shell sets html.duo + duo-folded/duo-open and --duo-col-left/right; useDuo() subscribes then rereads startup classes, and html.duo CSS owns presentation. DuoPanelContext forces phone panels; DuoSchedulePanel mirrors Schedule.tsx's mobile branch. Manager dash is folded-only; Layout owns the open split header and handles open-profile-menu through the mobile Sheet in either mode. Why: one additive shell contract without startup races or desktop-menu fallback, zero changes when duo is absent.
- Duo open grids use the same viewport-centered crease calculation for header and panels, subtracting the left column and half the crease gutter from 50vw. Why: the native column must not move the split away from the physical fold.
- Duo open header Nudge uses the existing Sheet in non-modal mode with crease-bounded CSS; all other Nudge presentations retain their original modal behavior. Why: allow outside dismissal and header toggling without changing sending logic.
