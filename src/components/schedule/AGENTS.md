- Schedule change history is written only by DB triggers on scheduled_shifts/schedules and the schedule RPCs; clients never write schedule_change_log. Undo/revert only via useScheduleRestore → restore_schedule / undo_schedule_change, and never on live weeks (live changes go through Update); never on worked days or shifts with punches. The original publish lives in schedules.original_* and is set only by trg_schedules_lifecycle. Why: every change is tracked and auditable no matter which screen made it.
- Schedules go live only through public._publish_schedule (called by publish_schedule / approve_schedule); the client posts only via rpc('publish_schedule') (scheduleActions.publishSchedule) or useScheduleApproval, never by updating is_published; approval fields change only via submit_schedule_for_approval / approve_schedule / send_back_schedule / set_schedule_approval_settings, and trg_schedules_lifecycle rejects gated direct publishes. Why: per-store approval can't be bypassed and the approved publish becomes the original.
- Scheduled paid hours (unpaid meals from the store's labor_rules) come only from src/utils/shiftUtils.ts paidShiftHours (client, rules via useScheduleLaborRules) and public.scheduled_paid_hours (SQL, used by schedule_week_labor_check); the two are kept identical. Why: the Labor row and the approval check must show the same hours and cost.
